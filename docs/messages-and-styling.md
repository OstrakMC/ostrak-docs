# Тексты и оформление сообщений

Ни один текст, который видит игрок, не зашит в код — весь он в
`plugins/OstrakFree/lang/ru_RU.yml`. Меняйте смело: это не код, а стиль
вывода. Свой перевод/стиль — не редактируйте `ru_RU.yml` напрямую, а
скопируйте его рядом под другим именем (например `lang/en_US.yml`),
отредактируйте и укажите в `config.yml` → `language: en_US`. Так обновление
плагина не затрёт вашу версию — файл `ru_RU.yml` плагин пересоздаёт при
каждом старте, только если его удалили, остальные файлы в `lang/` не трогает.

## Цвет и оформление — MiniMessage

Цвета, градиенты, жирный/курсив и т.д. — через теги
[MiniMessage](https://docs.advntr.dev/minimessage/format.html):

```yaml
common:
  no-permission: "<#F87171>✖ Недостаточно прав.</#F87171>"
```

- HEX-цвет: `<#RRGGBB>текст</#RRGGBB>`
- Именованный цвет: `<red>`, `<green>`, `<gray>`, `<dark_gray>`...
- Градиент: `<gradient:#38BDF8:#C084FC>текст</gradient>` (можно несколько
  остановок цвета через двоеточие)
- Декорации: `<bold>`, `<italic>`, `<underlined>`

## Старый формат тоже работает

Классические `&`-коды (`&c`, `&l` и т.д.) по-прежнему понимаются — можно не
переучиваться. Понимается и посимвольный HEX-градиент из генераторов
градиентов для Minecraft-чата вида:

```
&#54daf4O&#54cbecs&#54bbe5t&#54acddr&#549cd5a&#548dcdk
```

Такую строку можно вставить как есть — конвертируется в MiniMessage-теги
автоматически перед показом.

## Подстановки

Через `{скобки}` — набор для каждого ключа описан комментарием строкой выше
в файле. Лишние/недостающие подстановки ничего не ломают.

## Префикс

Перед каждым сообщением плагина (кроме разделителя — см. ниже) автоматически
идёт префикс:

```yaml
common:
  prefix: "<gradient:#38BDF8:#818CF8:#C084FC>◆ Ostrak</gradient> <dark_gray>»</dark_gray> "
```

Можно поменять текст, цвет или сделать градиент — он парсится тем же движком,
что и остальные сообщения.

## Разделитель

`common.divider` — строка перед/после многострочных блоков (список
документов, `/ostrak help`, `/ostrak diagnostics`, `/registry search`),
чтобы несколько сообщений подряд не сливались в один нечитаемый ком текста.

- Совсем пустая строка (`""`) — разделитель не отправляется вовсе.
- Строка из пробела (`" "`, значение по умолчанию) — просто пустая строка
  вместо декоративной черты.
- Можно поставить и настоящую черту:
  ```yaml
  common:
    divider: "<dark_gray>▬▬▬▬▬▬▬▬▬</dark_gray> <gradient:#38BDF8:#C084FC>◆</gradient> <dark_gray>▬▬▬▬▬▬▬▬▬</dark_gray>"
  ```

## Перенос строки

`\n` внутри одного сообщения (только в двойных кавычках — в одинарных YAML
не превращает `\n` в перенос).

## Опечатка в ключе

Если удалить ключ или испортить YAML — на экране игрока вместо текста
появится сам ключ (например `common.no-permission`). Так пропажа видна
сразу, а не тонет молча.

## Единая палитра по умолчанию

Все сообщения плагина уже покрашены по единой схеме — если просто хотите
что-то донастроить, а не переписывать с нуля:

| Тип сообщения | Цвет | Значок |
|---|---|---|
| Успех | зелёный `#34D399` | ✔ |
| Ошибка | красный `#F87171` | ✖ |
| Предупреждение | янтарный `#FBBF24` | ⚠ |
| Информация | голубой `#38BDF8` | — |
| Второстепенный текст | приглушённый серый `#94A3B8` | — |
| Значения (имена, числа) | почти белый `#E2E8F0` | — |

`◆` используется как декоративный разделитель полей внутри строк (например,
в `/registry search` между типом документа и именем персонажа).
